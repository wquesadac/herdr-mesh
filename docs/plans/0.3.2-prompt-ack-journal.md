# herdr-mesh 0.3.2: prompt acknowledgement, reliable clear, task journal

Base: `feat/0.3.1-agent-placement`. Branch: `feat/0.3.2-prompt-ack-journal`. Version **0.3.2** in
`package.json` and `src/server.ts`. `dist/` is committed: rebuild it and commit it. No new dependencies.

## Why

The 0.3.1 live runs found two problems:
- **Swallowed prompt.** Cursor's "trust this workspace?" dialog took the task prompt. The agent stayed
  idle, and the task only failed when the 10-minute wait timed out.
- **Unconfirmed clear.** `clear` sent `/clear` and then `agent wait --until idle`. That wait returned at
  once, because the agent was already idle, so nothing confirmed the clear was processed before the task
  arrived.

There is also no durable, human-readable record of finished tasks. The orchestrator needs one to write
project memory.

## 1. Prompt acknowledgement (all placements)

A prompt counts as **acknowledged** once, after dispatch, either:
- `observed_working` is true; or
- `completion_seq` is above `baseline_completion_seq`.

TaskRecord changes:
- New optional fields: `prompt_attempts?: number` (dispatches so far) and `ack_ms?: number`.
- New input on `herdr_task_run`: `ack_ms` (integer, default 20000, minimum 5000), stored on the record.

Prompt text:
- Keep the built prompt text in the in-memory map (`pendingPrompts`, renamed to `promptTexts`) until the
  prompt is acknowledged or the task is final.
- If the server restarted and the text is gone, skip the resend logic. Today's behaviour stays.

Each `waitForRecords` tick, for a record that is not final, has no `pending_prompt`, and is not
acknowledged, once `now - dispatched_at >= ack_ms`:

| agent status | prompt_attempts | action |
|---|---|---|
| `blocked` | any | `observe(blocked)`. A dialog is up. When it later becomes idle/done (still unacknowledged), the rows below apply. |
| `idle` / `done` | < 2 | Resend the same text. Set `dispatched_at = now` and `prompt_attempts += 1`. Read the new baseline from the snapshot. |
| `idle` / `done` | >= 2 | `registry.finalize(record, "failed", { summary: "prompt not received after 2 attempts" })` |
| `working` / `unknown` | any | nothing (`working` sets `observed_working` as today) |

This check runs **before** `detectFinish` for that record. While a record is unacknowledged and inside
its `ack_ms` window, an idle status must not produce `missing_result`.

Counting:
- The first dispatch, whether in `herdr_task_run` or in the pending-prompt path, sets `prompt_attempts = 1`.
- The pending-prompt dispatch counts as a dispatch: it sets `prompt_attempts` and `dispatched_at`.

Export a pure function `ackDecision(snapshot, record, now)` that returns
`"acked" | "wait" | "resend" | "blocked" | "fail"`. Unit-test it for every row of the table, and for:
- acknowledgement by `completion_seq` without ever being observed working;
- an agent that is still inside the window.

## 2. Reliable clear (`agent` placement)

Replace the clear block in `placeOnAgent`:
1. `agent get <name>` and record `state_change_seq` (parse it in `parseLiveAgent`; it is a number in
   `agent get` output).
2. `agent prompt <name> <clear>`.
3. Poll `agent get` every 500 ms, for up to 10 s, until `state_change_seq` exceeds the recorded value.
4. Then `agent wait <name> --until idle --until done --timeout 30000`.
5. If step 3 never saw a change, still continue after a 3 s settle delay. Set
   `clear_unconfirmed: true` on the record and include it in the task output, so the caller knows.

Export the pure helper `clearSettled(before: number | undefined, after: number | undefined): boolean` and test it.

## 3. Branch cleanup after a failed hand-off (`agent` + `worktree`)

If `herdr_task_run` created a git worktree and branch, and then fails before the prompt is delivered
(clear failure, prompt error), clean up:
1. Run `git worktree remove <path>`.
2. Delete the branch with `git branch -D <branch>`, but only when the branch tip equals the base commit
   recorded at creation.
   - Record `base_sha` at creation with `git rev-parse <base or HEAD>`.
   - Otherwise keep the branch.

This lets a retry reuse the branch name. Export `shouldDeleteFailedBranch(tipSha, baseSha)` and test it.

## 4. Task journal

New optional input on `herdr_task_run`: `journal` (absolute directory path). It is stored on the record
as `journal_dir`.

In `TaskRegistry.finalize`, if `record.journal_dir` is set, append one markdown entry to
`<journal_dir>/<YYYY-MM-DD>.md` (local date of `finished_at`). Create the directory if it is missing,
and create the file with a first line `# Task journal <date>`. Entry format:

```
## HH:MM <name> (<kind>): <status>
- dir: <cwd> · branch: <worktree.branch or "-"> · elapsed: <formatElapsed>
- commits: <comma list or "-">
- files: <count> (<first 5, comma list>)
- summary:
  <summary, each line indented two spaces, at most 30 lines>
- questions: <one line each, or "-">
- followups: <one line each, or "-">
```

Rules:
- `finalize` gets the full parsed result. Widen its `result` parameter to the contract's result type
  plus `summary?`.
- `close` without a prior finish appends an entry with status `closed` and no result fields.
- Journal write errors are swallowed. A journal failure must never fail a task.
- Export `formatJournalEntry(record, result, now)` (pure) and test it: full result, no result,
  summary longer than 30 lines, missing commits.
- README: suggest a git-ignored directory such as `<repo>/.agent/journal`. The orchestrator then
  curates it into committed project memory.

## 5. Output

- `TaskOutput` gains `prompt_attempts` when it is more than 1, and `clear_unconfirmed` when true.
- `herdr_task_status` lines show `running (awaiting ack)` while a record is unacknowledged and
  past its first dispatch.
