# herdr-mesh 0.3.1 — hand a task to an already-running agent

Base: `feat/0.3.0-task-tools`. Branch: `feat/0.3.1-agent-placement`. Version **0.3.1** in
`package.json` and `src/server.ts`. `dist/` is committed: rebuild and commit it. No new dependencies.

## Why

Users keep long-lived agent panels (e.g. `cursor-tarif`, `agy-tarif`, `opencode-tarif`, all in the
main checkout). `herdr_task_run` can only start a new agent. 0.3.1 lets it hand a task to a running
agent, optionally in a fresh git worktree so the agent doesn't edit the main checkout, and optionally
clearing the agent's conversation first so each task starts small.

## `herdr_task_run`: new placement `agent`

Placement becomes exactly one of `cwd`, `worktree`, `pane_id`, or **`agent`** (string: a live agent
name or pane id). With `agent`:
- Do **not** start an agent; `name` must equal the agent's live name. If `agent` is a pane id, resolve
  the live name with `herdr agent get <agent>` and require it to equal `name`. `kind` and `args` are
  optional and ignored (record the kind from `agent get`).
- The agent must be `idle` or `done`. Otherwise fail with
  `agent <name> is <status>; wait for it to be idle`. Never interrupt a working agent.
- Work directory:
  - `worktree: { repo, branch, base?, path? }` given (allowed together with `agent`): run
    `git -C <repo> worktree add -b <branch> <path> [<base>]`, where `path` defaults to
    `<parent of repo>/<repo basename>-<branch with "/" replaced by "-">`. If the branch already exists,
    fail and do not create anything. The work directory is that path. Record
    `worktree: { path, branch, base, created_by: "git" }`.
  - otherwise: the agent's `cwd` from `agent get`.
- `clear?: string`: a command to send first (e.g. `"/clear"` or `"/new"`). If given: run
  `agent prompt <name> <clear>`, then `agent wait <name> --until idle --until done --timeout 30000`.
  If that times out, fail before sending the task. No default and no per-kind guessing; the README
  lists the known commands as examples to try.
- Prompt: when the work directory differs from the agent's own cwd, prepend one line to the task text:
  `Work only in <dir> (a git worktree on branch <branch>): cd there for every command and edit files only under it.`
  Then `buildTaskPrompt` as today. `result_path` resolves against the **work directory**.
- Registry: `placement: "agent"`, `pane_id`/`workspace_id` from `agent get`, `created` unset (the
  agent belongs to the user), `cwd` = work directory. The baseline `completion_seq` is read **after**
  the clear step.

## `herdr_task_close`

- `placement: "agent"` never closes a pane, tab or workspace.
- `remove_worktree: true` with `worktree.created_by === "git"`: the same dirty / unpushed checks as
  today (`worktreeStatusArgv`, `rev-list --count HEAD --not --remotes`; refuse unless `force`). Then
  run `git -C <repo> worktree remove [--force] <path>`. Never delete the branch.
- `remove_worktree: true` on placements without a worktree: refuse with a clear message (as today).

`closeDecision` gains the action `"git_worktree_remove"`. Keep it a pure function and test it.

## Tests (`test/task.test.ts`, no herdr needed)

- Placement validation: `agent` plus `cwd`, or `agent` plus `pane_id`, is rejected; `agent` plus
  `worktree` is accepted.
- `agentWorktreePath(repo, branch)`: `/w/repo` + `feat/x` → `/w/repo-feat-x`.
- `workPrefix(dir, branch)` returns the exact line above; there is no prefix when the directory equals
  the agent cwd.
- `closeDecision`: agent placement without a worktree → `none`; with a git worktree and
  `remove_worktree` → `git_worktree_remove`; a dirty tree without `force` → refuse.
- A real-git test (temp repo, like the existing dirty-check test): `git worktree add` with the argv
  builder, then the remove argv, leaves the branch in place.

Export the small pure helpers (argv builders, path, prefix) so they can be tested. Keep the live
herdr calls thin.
